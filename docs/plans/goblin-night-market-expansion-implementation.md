## 적용한 변경

- 기본 보드를 28칸·16가게·12밤으로 확장했다. 업종마다 네 가게를 두고 전부 보유하면 요금 +1이다. 유행은 네 업종을 한 번씩 섞은 묶음 세 개다.
- 점검 모형과 같은 칸 배치를 적용했다. 만물장터 7·20, 지름길 14·27, 낮잠 정자 21, 소문 골목 여섯 곳, 공동 출발 위치 0·7·14·21이다.
- 새 가게는 이슬 한과방·별실 공방·소원 등불집·반딧불 놀이방이다. 매입 6·증축 4·밑천 3·카드 각 6장·손패 2장·둔갑 절반 정산·마지막 가게 보호는 유지했다.
- 선택 시간은 주사위 5초, 매입/지름길/대결/강제 매각 15초, 증축 10초, 손패 정리 8초다. 시간 만료 시 기존 기본 행동을 사용하고, 이미 확정한 대결 카드는 유지한다.
- 8×8 테두리의 28칸 보드와 12밤 진행 표시, 가게 목록, 요금·교환 표시, 규칙 설명, 홈·대기실과 혼자 보는 미리보기를 새 규칙에 맞췄다.

## 진행 중인 경기와 재경기

각 상태의 rulesVersion에서 보드·가게 이름·밤 수·업종 완성 조건·타이머를 읽는다. 기존 mvp-1의 저장 상태는 변환하지 않고 20칸·12가게·8밤·기존 타이머로 이어간다. 새 경기와 재경기부터 mvp-2를 사용한다. 두 버전의 저장 상태를 같은 렌더러와 판정기로 처리한다.

API의 칸 입력 범위는 0–27까지 허용하지만, 실제 행동은 그 경기 버전에서 유효한 가게인지 다시 검증한다. 따라서 기존 경기에서 새 칸 번호를 입력해 가게를 얻거나 이동할 수는 없다.

## 검증

- 전체 Vitest **39개 파일·230개 테스트 통과**. 새 확장판 검사 28개와 확장 보드 UI·기존 저장 경기 재경기 호환 검사를 포함한다.
- Python 점검 모형의 3·4인 각 네 경기, 총 **8판·행동 1,095개**를 production reducer에서 재생했다. 매 밤 자산, 최종 현금·가게 소유권/증축·위치·손패·덱·버림 더미·최종 자산이 일치했다.
- 재생의 난수 기록은 주사위 합·매 밤 순서·카드 종류별 재섞기를 두 런타임에서 동일하게 맞춘다. 합성 초기 상태와 공개 행동만 사용한다. 참조 기록은 일부러 현금이 부족하지 않은 경기이며 강제 매각은 별도 단위 검사로 확인한다.
- 모든 새 특수 칸, 28칸 순환과 달문 보너스, 네 채 완성 요금, 15초 대결의 확정 유지, 8밤 이후 계속 진행과 12밤 종료를 확인했다.
- 기존 mvp-1 저장 상태의 이름·요금·20칸 이동·기존 종료와 재경기 시 mvp-2 전환을 확인했다.
- 실제 HTTP API에서 **3인·4인 각각 12밤 완주·최종 정산·재경기**를 확인했다. Display 권한으로 private 요청을 보내도 공개 투영만 반환했다.
- TypeScript 검사와 Next.js 16.2.11 프로덕션 빌드 통과.

브라우저에서 28칸·12밤 보드와 모바일 카드 선택·절반 정산을 확인했다. 캡처는 [확장 보드](./assets/goblin-market-expanded-board.jpg), [모바일 손패](./assets/goblin-market-expanded-mobile.jpg)에 보관한다.

## 참조 기록 재현

```bash
PYTHONDONTWRITEBYTECODE=1 python3 scripts/generate_goblin_expansion_fixture.py
node node_modules/vitest/vitest.mjs run src/modules/goblin-market src/modules/room/goblin-market-service.test.ts
node node_modules/typescript/bin/tsc --noEmit
node node_modules/next/dist/bin/next build
```

개발 서버 실행 후 `node scripts/goblin-market-http-smoke.mjs http://127.0.0.1:3100`으로 합성 참가자를 사용한 실제 API 검사를 반복할 수 있다. `src/modules/goblin-market/domain/fixtures/expanded-golden.json`에는 점검 엔진과 생성 스크립트의 SHA-256을 기록했다. 기존 밸런스 엔진과 원시 자료는 수정하지 않았다.

사람 경기 시간, 넉넉한 타이머에서의 실제 자동 패스 빈도, 업종 완성의 재미, 뒤처진 사람의 선택과 집중 견제는 다음 사람 플레이테스트에서 확인한다. 기능 검증 완료를 전체 전략 균형 완성으로 표현하지 않는다.
