# 네 번째 게임: 한밤의 발자국

## 목표

- 장난스러운 괴도와 경비가 겨루는 2인 전용 비대칭 추리 대결이다.
- 한 매치는 역할을 교대하는 2라운드로 구성하고, 두 라운드의 침입 성과를 비교해 승자를 정한다.
- 첫 침입자는 무작위, 재경기에서는 시작 역할 순서를 반전한다.
- 지도는 3개 중 무작위로 선택하며 두 라운드 동안 동일하다. 재경기에서는 직전 지도를 제외한다.

## 턴 정의

라운드의 턴은 침입자 행동 횟수로 센다. 입장과 훔치기도 각각 한 턴이다.

- 준비 단계: 역할을 확인하고 침입자는 비밀 입구를 고른 뒤 두 플레이어가 준비한다.
- 두 플레이어가 준비되면 선택한 입구로 들어가는 행동을 턴 1로 확정한다.
- 각 턴은 `침입자 행동 → 흔적 또는 경보 공개 → 경비 행동` 순서로 진행한다.
- 홀수 턴에는 행동을 마친 방의 구역 흔적, 짝수 턴에는 바닥 흔적을 공개한다.
- 훔치기 턴에는 일반 흔적 대신 목표물과 정확한 방을 공개한다.
- 유효한 출구에 도착하면 흔적 공개와 경비 행동 없이 즉시 탈출한다.
- 10번째 침입자 행동 직후 탈출하지 못했으면 흔적 공개와 경비 행동 없이 즉시 시간 초과다.
- "최단 성공 X턴"은 입장과 훔치기를 포함한 침입자 행동 X회로 탈출을 완료한다는 뜻이다.

## 라운드 진행

```text
역할 확인·준비
→ 침입자 비밀 입구 선택
→ [턴 반복] 침입자 행동 → 흔적 또는 경보 공개 → 경비 행동
→ 탈출 / 체포 / 포위 / 시간 초과
```

### 침입자 행동

- 인접 방으로 1칸 이동
- 잠복(라운드당 2회): 이동하지 않고 정상 흔적 생성
- 훔치기: 한 턴 소비, 현재 방에 있는 목표물을 훔치며 목표물과 정확한 방을 즉시 공개

### 경비 행동

- 최대 2칸(0칸 포함) 이동 후 최종 도착 방만 수색
- 이동·수색 대신 현재 방에 인접한 내부 통로 봉쇄(라운드당 2회)
- 봉쇄된 통로는 침입자와 경비 모두 통행할 수 없다.
- 봉쇄는 다음 침입자 행동과 그 뒤의 경비 행동까지 유지되고, 해당 경비 행동이 끝나면 자동 해제된다.
- 경비가 점유한 방은 침입자가 진입 불가
- 실패한 수색은 `빈 방`만 알려주며 거리 힌트 없음
- 경비가 이동 중 침입자의 방을 통과해도 체포가 아니다. 체포는 최종 도착 방 수색으로만 성립한다.

## 흔적과 지도

9개 방은 고유한 `구역 × 바닥` 조합을 가진다.

| 구역 | 나무 | 카펫 | 타일 |
|---|---|---|---|
| 서쪽 | 서재 | 침실 | 욕실 |
| 중앙 | 거실 | 중앙홀 | 주방 |
| 동쪽 | 작업실 | 응접실 | 세탁실 |

- 훔치기 경보는 해당 턴의 일반 흔적을 대체한다.
- 자동 후보 계산은 제공하지 않는다. 대신 공개 화면에 흔적 히스토리 타임라인을 반드시 제공한다.
- 경비는 개인 화면에서 방을 `유력·제외·미확인`으로 표시한다.
- 개인 메모는 서버에 비밀로 저장하고 역할 교대 시 초기화한다.

지도는 다음 세 가지 완성형 레이아웃이다.

- 열린 회랑
- 엇갈린 복도
- 고리 저택

방과 흔적 체계는 공유하지만 통로·입구·목표물·경비 시작 위치는 지도별로 고정한다.

### 지도 제약과 기계 검증

세 지도는 구현 착수 전에 데이터로 확정하고, 아래 제약을 전수 탐색 스크립트로 검증한다.

- 세 입구 중 둘 이상은 같은 구역에 둔다. 첫 구역 흔적만으로 입구 방이 특정되면 안 된다.
- 모든 목표물 방은 진입로가 2개 이상이어야 한다. 경비의 단일 방 점유로 목표물이 원천 봉쇄되면 안 된다.
- 목표물별 최단 성공 턴은 지도에서 가능한 `입구 → 목표물 → 다른 출구` 조합의 최소값으로 계산한다.
- 2점·4점·6점 목표물의 최소값은 각각 5턴·6턴·7턴이어야 하며, 어느 입구를 골라도 해당 목표물의 최단 성공 경로가 기준보다 2턴을 초과하지 않아야 한다.
- 모든 `(목표물, 최초 입구)` 조합에서 최초 입구를 제외한 두 출구 각각으로 향하는 단순 경로가 하나 이상 있어야 한다.
- 두 탈출 경로는 목표물 방 외의 중간 방을 공유하지 않아야 한다. 같은 병목을 공유하는 우회로는 서로 다른 경로로 세지 않는다.
- 초기 상태부터 특정 입구가 침입자 또는 경비의 승리를 강제해서는 안 된다.
- 훔치기 이후의 모든 상태에서 탈출을 보장하지 않는다. 경비의 추리·점유·봉쇄 결과에 따라 강제 체포 또는 포위가 가능한 상태도 정상적인 게임 결과다.
- 전수 탐색은 양쪽 모두 합법 행동과 승리 가능한 분기를 갖는 초기 상태인지 검증하고, 실제 승률은 플레이테스트로 판단한다.
- 세 지도 중 최소 하나에는 출입구가 아닌 차수 2의 방이 있어야 한다. 경비의 방 점유와 인접 통로 봉쇄로 잠복을 모두 사용한 침입자를 포위하는 행동 시퀀스가 실제로 가능해야 한다.

## 목표물과 탈출

- 2점: 은화 주머니 — 최단 성공 5턴
- 4점: 별빛 목걸이 — 최단 성공 6턴
- 6점: 황금 고양이상 — 최단 성공 7턴

목표는 미리 지정하지 않고 처음 훔친 하나로 확정한다. 이후 추가 훔치기는 불가하다.

출구는 훔치기 성공 이후에만 활성화된다.

- 훔치기 전에는 출구 방(자신의 입구 포함)에 도착해도 일반 이동이다.
- 훔친 뒤 최초 진입 지점과 다른 두 출입구 중 하나에 도착하면 경비의 추가 행동 없이 즉시 탈출 성공한다.
- 훔친 뒤 자신의 입구 방에 도착하는 것은 일반 이동이며 탈출이 아니다.

빈손 탈출은 존재하지 않는다. 훔치지 못한 라운드는 탈출 실패다.

## 포위

침입자가 자기 턴에 합법 행동(이동·잠복·훔치기)이 하나도 없으면 포위다. 포위는 체포와 동일하게 취급하며, 실패 성과에는 포위 판정 전까지 완료한 침입자 행동 수를 기록한다.

## 최종 판정

두 라운드의 침입 성과를 비교한다. 라운드 결과는 `탈출(목표물 가치, 완료한 행동 수)` 또는 `실패(완료한 행동 수)` 둘 중 하나다.

1. 한쪽만 탈출했으면 탈출한 쪽이 승리한다.
2. 둘 다 탈출했으면 목표물 가치가 높은 쪽, 같으면 적게 사용한 턴 쪽이 승리한다.
3. 둘 다 실패했으면 완료한 침입자 행동 수가 많은 쪽이 승리한다.
   - 행동 N 이후 경비 수색으로 체포되면 N을 기록한다.
   - 행동 N 이후 다음 침입자 차례 시작 시 포위되면 N을 기록한다.
   - 10번째 행동 후 시간 초과되면 10을 기록한다.
   - 체포·포위·시간 초과 시 이미 훔친 목표물의 가치는 판정에 반영하지 않는다.
4. 모두 같으면 무승부다.

생각한 시간은 공개 화면에 표시하지만 승패에는 사용하지 않는다.

## 세션과 운영

- 재경기는 두 사람 모두 동의해야 시작한다.
- 목표물 점수는 매치마다 초기화하고, 세션에는 승·무·패 전적만 누적한다.
- 전체 침입 경로는 두 라운드가 모두 끝난 뒤 함께 공개한다.
- 현재 heartbeat 정책에 따라 마지막 응답 후 45초가 지나면 연결 해제로 판정하고 즉시 게임을 일시정지한다.
- 연결 해제로 판정된 시점부터 3분 뒤 남은 플레이어가 상대 기권 종료를 청구할 수 있다.
- 같은 사용자 세션으로 돌아오면 기존 역할·위치·개인 메모를 복구하고 일시정지를 해제한다.
- 접속 중인 플레이어의 행동 시간에는 강제 제한을 두지 않는다. 현재 행동자가 생각한 시간만 공개 화면에 표시하며 승패와 기권 조건에는 사용하지 않는다.
- 따라서 탭을 열어 둔 채 행동하지 않는 상대에게 기권을 청구할 수 없는 위험을 v1에서 명시적으로 수용한다.

## 상태와 정보 공개

`src/modules/midnight-footprints` 독립 모듈로 구성한다.

### 상태 머신

```text
ROUND_SETUP
  └─ 두 플레이어 준비 + 비밀 입구 선택
      └─ 입장을 턴 1로 처리하고 첫 구역 흔적 공개
          ↓
GUARD_TURN
  ├─ 이동 후 수색 성공 ───────────────────────→ ROUND_RESULT
  ├─ 봉쇄
  └─ 이동 후 수색 실패
          ↓
INTRUDER_TURN
  ├─ 이동 / 잠복 / 훔치기 ─→ 흔적·경보 공개 ─→ GUARD_TURN
  ├─ 유효 출구 도착 ─────────────────────────→ ROUND_RESULT
  ├─ 합법 행동 없음 ─────────────────────────→ ROUND_RESULT
  └─ 10번째 행동 후 미탈출 ──────────────────→ ROUND_RESULT

ROUND_RESULT
  ├─ 1라운드 결과 양쪽 확인 ─────────────────→ ROUND_SETUP
  └─ 2라운드 결과 양쪽 확인 ─────────────────→ MATCH_RESULT

MATCH_RESULT
  ├─ 두 플레이어가 재경기 동의 ──────────────→ ROUND_SETUP
  └─ 한 명 이상 종료 선택 ───────────────────→ GAME_OVER
```

연결 해제는 별도 게임 phase로 덮어쓰지 않고 `pause` 상태로 관리한다. `pause`에는 연결이 끊긴 좌석, 판정 시각, 기권 청구 가능 시각을 저장한다. 일시정지 중에는 재접속과 `CLAIM_FORFEIT` 이외의 게임 행동을 거부하며, 재접속하면 중단 전 phase와 행동 시작 시각으로 돌아간다.

핵심 행동:

```ts
SELECT_ENTRY
MARK_READY
MOVE_INTRUDER
HIDE
STEAL
MOVE_AND_SEARCH
BLOCK_PASSAGE
ACK_ROUND_RESULT
CAST_REMATCH_VOTE
CLAIM_FORFEIT
```

탈출·체포·포위·시간 초과는 별도 행동 없이 해당 행동 처리 시 자동 판정한다.

경비의 `SET_ROOM_MARKS`는 게임 행동과 분리된 플레이어별 비밀 보조 상태 변경이다.

- 경비 역할인 동안 `INTRUDER_TURN`과 `GUARD_TURN`에서 모두 사용할 수 있다.
- 현재 9개 방의 표시를 한 번에 교체하며 이동·수색·봉쇄 행동이나 턴을 소비하지 않는다.
- 게임 스냅샷의 `room.version`을 증가시키지 않고 별도의 private player-state revision으로 저장한다.
- 침입자 게임 행동과 메모 저장이 동시에 발생해도 서로 stale version을 만들지 않아야 한다.
- 역할 교대와 새 매치 시작 시 해당 라운드의 메모를 초기화한다.

### 공개 투영

공개 화면과 TV 화면에는 다음 정보만 반환한다.

- 현재 매치·라운드·턴·phase와 현재 행동자
- 플레이어 닉네임, 공개 역할, 접속·준비 상태와 세션 전적
- 지도, 목표물 위치와 가치, 경비 위치, 활성 봉쇄와 남은 봉쇄 횟수
- 흔적 히스토리, 실패한 수색, 공개된 훔치기 경보와 라운드 결과
- 현재 행동 시작 시각, 일시정지 상태와 기권 청구 가능 시각
- 재경기 투표 제출 인원만 표시하고 개별 선택은 숨김
- 두 번째 라운드가 끝난 `MATCH_RESULT`와 `GAME_OVER`에서만 두 라운드의 전체 침입 경로 공개

### 개인 투영

- 침입자에게만 현재 방, 최초 입구, 합법 이동 방, 남은 잠복 횟수, 훔친 목표물과 본인의 경로를 반환한다.
- 경비에게만 방별 개인 메모, 합법 이동 경로, 봉쇄 가능한 인접 통로를 반환한다.
- 각 플레이어에게 본인이 제출한 준비·결과 확인·재경기 투표 상태만 반환한다.
- 침입자의 현재 위치·최초 입구·공개 전 경로, 상대의 재경기 선택, 경비의 개인 메모는 공개 응답·로그·룸 이벤트에 포함하지 않는다.

### 게임 런타임 연결

네 번째 게임을 추가하기 전에 `game-runtime/server.ts`의 마지막 `else`가 `dawn-switchboard`를 의미하는 구조를 제거한다. `createGame`, `advanceGame`, `transitionGame`, 공개 투영과 개인 투영을 게임 ID별 명시적 `switch`로 바꾸고 `assertNever`로 누락된 게임을 컴파일 단계에서 실패시킨다. 범용 게임 엔진이나 플러그인 레지스트리는 만들지 않는다.

### 재경기와 룸 상태

기존 호스트 전용 `START_REMATCH`는 이 게임에서 사용하지 않고 게임 상태 내부의 양자 재경기 투표로 세션을 이어간다.

- `MATCH_RESULT`에서는 `isGameOver`가 `false`이며 룸 상태도 `playing`을 유지한다.
- 두 플레이어가 모두 재경기에 동의하면 reducer가 직전 지도를 제외하고 시작 역할을 반전한 새 매치를 만든다.
- 한 명 이상 종료를 선택해 `GAME_OVER`가 된 뒤에는 카탈로그의 게임별 rematch 정책과 룸 서비스가 `START_REMATCH`를 거부한다.
- UI는 호스트 여부나 `GAME_OVER`만 보고 재경기 버튼을 그리지 않고 서버가 제공한 `legalAdministrativeActions`를 따른다.
- 세션이 완전히 종료된 뒤 다시 플레이하려면 메인 화면에서 새 방을 만든다.

## 테스트 계획

```text
지도 데이터
  └─ 연결성·입구 모호성·목표물 경로 전수 검사
      ↓
순수 reducer
  └─ 모든 합법 행동·자동 판정·두 라운드·재경기
      ↓
공개/개인 투영
  └─ 위치·입구·경로·메모·투표 비밀정보 누출 검사
      ↓
룸 서비스
  └─ 2인 제한·중복/오래된 행동·일시정지·기권·재경기 권한
      ↓
Playwright 2-context
  └─ 입장부터 역할 교대·결과·재경기·세션 종료까지
```

### 단위·속성 테스트

- 세 지도는 연결 그래프이며 입구·목표물·경비 시작 위치가 유효한 방인지 검사한다.
- 첫 구역 흔적으로 입구가 하나로 확정되지 않는지 검사한다.
- 목표물별 5턴·6턴·7턴 최소 경로와 입구별 최대 편차 2턴을 전수 검사한다.
- 모든 `(목표물, 최초 입구)` 조합에서 서로 다른 두 유효 출구로 향하고 목표물 외의 중간 방을 공유하지 않는 경로 쌍이 존재하는지 검사한다.
- 최소 한 지도에서 차수 2의 비입구 방을 이용한 포위 시퀀스가 성립하는지 검사한다.
- 준비와 입구 선택 순서, 입장을 포함한 턴 계산, 홀수·짝수 흔적과 훔치기 경보 대체를 검사한다.
- 잠복 2회 제한, 봉쇄 2회 제한과 자동 해제 시점, 경비 점유 방 진입 금지를 검사한다.
- 경비의 중간 경유 방은 체포하지 않고 최종 수색 방만 체포하는지 검사한다.
- 빈손 탈출 금지, 다른 출구 즉시 탈출, 10번째 행동 시간 초과, 합법 행동 없는 포위를 검사한다.
- 직접 체포·포위·시간 초과가 완료한 침입자 행동 수를 각각 N·N·10으로 기록하는지 검사한다.
- 역할 교대, 최종 판정의 모든 동점 분기, 지도 제외와 시작 역할 반전을 검사한다.
- 일시정지 중 행동 거부, 재접속 복구와 기권 가능 시각 경계를 검사한다.

### 투영·서비스 테스트

- 매치 종료 전 공개·상대 개인 응답에 침입자의 현재 위치·입구·경로가 없는지 검사한다.
- 경비 메모와 개별 재경기 투표가 공개 응답·상대 응답·로그·Realtime 이벤트에 없는지 검사한다.
- 침입자 행동과 `SET_ROOM_MARKS`를 동시에 저장해도 게임 version 충돌이나 메모 유실이 없는지 검사한다.
- `SET_ROOM_MARKS`가 두 행동 phase 모두에서 허용되고 경비의 게임 행동을 소비하지 않는지 검사한다.
- `MATCH_RESULT` 전에는 경로가 숨겨지고 이후에만 두 경로가 공개되는지 검사한다.
- 동시에 세 번째 사용자가 입장할 때 `ROOM_FULL`로 거부되는지 검사한다.
- 중복 action ID, stale version, 잘못된 역할·phase 행동과 빠른 연속 제출을 검사한다.
- 이 게임의 `START_REMATCH`가 UI 노출뿐 아니라 API 직접 호출에서도 거부되는지 회귀 테스트한다.
- heartbeat 44초·45초 경계, 연결 해제 판정 후 3분 경계, 호스트 승계와 기권 처리를 검사한다.

### E2E

- Playwright 브라우저 컨텍스트 두 개로 탈출 성공, 직접 체포, 포위, 시간 초과를 각각 완료한다.
- 두 라운드에서 역할이 교대되고 첫 라운드 경로가 두 번째 라운드에 노출되지 않는지 검사한다.
- 두 명 모두 재경기에 동의한 흐름과 한 명이 종료한 흐름을 검사한다.
- 세 레이아웃을 최소 한 번씩 실행하고 개인 화면·공개 화면·TV 화면을 전환해 비밀정보가 노출되지 않는지 검사한다.

## 기존 구조 재사용

- 게임 카탈로그의 `minPlayers`·`maxPlayers`로 정확히 두 명만 입장시킨다.
- QR·공유 링크, 익명 인증, 좌석 재접속, 호스트 승계와 방 만료는 기존 룸 모듈을 재사용한다.
- 전체 게임 상태를 서버 스냅샷에 두고 공개·개인 화면에 허용된 필드만 투영하는 구조를 재사용한다.
- 게임 행동에는 action ID 중복 방지, room version 검사와 Supabase 트랜잭션을 그대로 사용한다. 경비 메모는 별도의 private player-state revision을 사용한다.
- 휴대폰의 개인·공개 화면 전환과 선택적 TV display 화면을 재사용한다.

## 범위에서 제외

- 채팅과 보이스 룸
- 절차적으로 생성되는 지도와 사용자 제작 지도
- 가짜 흔적, 카메라, 함정 등 추가 장비
- 가능한 침입자 위치의 자동 계산
- 행동별 강제 제한 시간
- 관전자와 3인 이상 팀전

## 구현 순서

1. 게임 런타임 분기를 명시적이고 완전한 `switch`로 변경한다.
2. 지도 데이터와 전수 탐색 검증 테스트를 작성한다.
3. 순수 TypeScript 상태·전이·점수 계산 테스트와 구현을 작성한다.
4. 게임 version과 분리된 플레이어별 비밀 메모 저장 경계를 구현한다.
5. 공개·침입자·경비 투영과 비밀정보 테스트를 작성한다.
6. 게임별 재경기 정책, 일시정지·기권 처리를 룸 서비스에 연결한다.
7. 개인 화면, 공개 보드와 TV 화면을 구현한다.
8. Playwright 2-context 전체 게임과 재경기 흐름을 검증한다.

## 밸런스 검증 기준

구현 전 플레이테스트 게이트:

- 총 12매치 기준 탈출률 40–60%, 평균 종료 6–9턴, 목표별 선택률 최소 15%
- 탈출률은 전체 수치와 함께 지도별로도 추적한다. 표본이 작으므로 지도별 편차는 참고 지표로 본다.

경비 우위가 확인될 때의 1순위 밸런스 레버는 `잠복 시 해당 턴 흔적 생략`이다. 기본 규칙은 잠복도 정상 흔적을 생성하지만, 매턴 흔적·경비 이동 2칸·수색 무비용이 겹쳐 경비가 구조적으로 유리할 수 있으므로 이 레버를 예비해 둔다.
