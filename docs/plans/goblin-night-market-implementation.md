## 플레이하는 방법

기존 앱의 홈에서 **도깨비 야시장 열기**를 선택한다. 방을 만든 사람도 닉네임을 정해 참가하고, QR이나 초대 링크로 3–4명이 모이면 호스트가 **모두 준비됨 · 야시장 개장**을 누른다. 각자 휴대폰에서 손패와 행동을 고르고 공개 보드를 함께 본다. TV용 화면은 선택 사항이다.

기본 메모리 저장소에서 개발 서버를 재시작하면 방이 사라진다. 같은 컴퓨터에서 여러 명으로 참가하려면 서로 다른 브라우저 프로필이나 시크릿 창을 사용한다. 휴대폰 연결을 위한 같은 Wi-Fi/LAN 주소 사용법은 루트 README를 따른다.

## 구현한 범위

- 3–4인 제한, 무작위 시작 가게·공동 출발 칸, 매 밤 독립 순서 추첨, 오늘/다음 유행 공개, 첫 밤 대결 유예, 여덟 밤 종료.
- 주사위 두 개 이동, 달문 보너스, 가게 매입·증축, 소문 골목·만물장터·지름길·낮잠 정자.
- 24장 덱, 전원 배분 후 순서대로 손패 두 장 정리, 공개 버림 더미 재순환, 장터 완판 시 카드 획득.
- 방문객/점주의 비밀 카드와 교환 대상 확정, 동시에 공개, 사용 카드 소비, 역할·소유권·증축 단계 검증.
- 둔갑 성공 시 교환 전 요금의 절반을 올림해 **교환 전 점주에게** 정산. 바가지 추가 요금 제외. 부적에 막히면 교환 없이 원래 요금 한 번 정산.
- 요금 부족 시 선택 매각, 마지막 가게 보호, 미지급액 면제, 최종 자산과 공동 우승, 새로운 경기 상태로 재경기.
- 서버 기준 타이머와 기본 행동. 대결 만료 시 이미 확정한 카드/대상은 유지하고 미확정자만 패스한다. 장기간 관측이 없었다면 다음 관측에서 만료된 선택 한 단계만 처리한다.
- 기존 방 저장·revision 비교·중복 요청 방지·개인/공개 화면에 연결. 다른 사람의 대결 제출로 방 version이 바뀌어도 같은 phaseKey의 유효한 내 선택을 재시도한다. 내 확정 선택은 새로고침 후 서버 투영에서 복구한다.

## 정보 경계

공개 투영은 위치·현금·자산·가게·손패 장수·현재 순서·오늘/다음 유행·공개 버린 카드·확정한 사람 수·공개 대결·기록만 반환한다. 덱 순서, 미래 유행/순서, 개인 손패, 공개 전 카드/교환 대상, userId는 반환하지 않는다. 개인 투영은 본인의 손패·확정 선택만 추가한다. 상대의 숨긴 선택으로 가능한 행동을 계산하지 않는다.

가게와 말에는 같은 고정 상인 번호를 붙이고 색상도 함께 사용한다. 이번 밤의 행동 순서는 별도로 표시한다.

## 재현

의존성이 설치된 프로젝트 루트에서 실행한다.

```bash
node node_modules/typescript/bin/tsc --noEmit
node node_modules/vitest/vitest.mjs run
node node_modules/next/dist/bin/next build
```

개발 서버를 실행한 뒤 별도 터미널에서 실제 HTTP 검사를 실행한다. 로컬 메모리 저장소 전용 검사이며 합성 참가자와 테스트 방을 만든다.

```bash
node node_modules/next/dist/bin/next dev --hostname 127.0.0.1 --port 3100
# 별도 터미널
node scripts/goblin-market-http-smoke.mjs http://127.0.0.1:3100
```

기존 Python 밸런스 엔진과 원시 결과는 수정하지 않았다. 다음 단계는 확정 규칙의 사람 플레이테스트 항목에 따라 3인·4인 각각 한 경기 이상을 실제로 진행하고 관찰을 기록하는 것이다.
